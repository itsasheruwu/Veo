# Windows parity tracker

Upstream: [itsasheruwu/Veo](https://github.com/itsasheruwu/Veo). Behavioral baseline: [`0e9b18dd345488613198ca6050b34e960e27f8b3`](https://github.com/itsasheruwu/Veo/commit/0e9b18dd345488613198ca6050b34e960e27f8b3), “Improve desktop workspace responsiveness and usability.”

This tracker preserves all 93 release requirements from the November 16, 2026 implementation brief. A record stays Pending until its complete workflow has evidence from the exact Windows artifact. Source inventory, a build, a visible button, and protocol-only tests do not establish physical UI parity. Split a record when its subfeatures need independent evidence.

## Environment and artifact

- Source checkout: isolated `Veo-Windows` checkout; pinned baseline verified before implementation.
- PC measurements: Windows reported `10.0.26300.0`, x64; .NET SDK `10.0.103`, runtime `10.0.3`; Visual Studio Community 2026 `18.3.2+11520.95`; Windows SDK Include `10.0.26100.0`; selected Desktop-bundled Codex `0.169.0`.
- Pinned inputs selected by the main implementation: Windows App SDK `2.6.5`, BuildTools `10.0.26100.7705`, WinApp `0.3.1`, MVVM Toolkit `8.4.0`, Markdig `0.41.3`, Microsoft.Data.Sqlite `10.0.0`, NAudio `2.2.1`. Restore/build and each integration proof must establish compatibility.
- Bootstrap: sandbox could not access the WinGet app alias; existing WinUI template/toolchain used.
- Git for Windows `2.52.0.windows.1`. The WebView2 application directory contained versions `141.0.3537.57` and `155.0.4283.45`. Exact-artifact evidence below records the registered package and binary hashes.
- Mac comparison: the pinned Swift source and checked-in `docs/assets/veo-workspace.png` supply the layout reference. A Veo-only Codex computer-use session over SSH to `astra-mac` also confirmed the installed Mac app's welcome screen, toolbar order and utility-panel browser chrome. The installed binary's equivalence to the pinned source is unverified.
- Physical ARM64, release signing identity, clean standard-user install, hardware audio and provider credentials require their own recorded checks.

## Completion rules

For each record, retain implementation locations, exact binary/package identity, reproducible acceptance steps, physical pointer and keyboard evidence, persisted-state or downstream readback, and any capability-dependent unavailability. Do not promote unavailable runtime methods to supported states or broaden access after sandbox failure. Never replay an uncertain send automatically.

The [machine-readable ledger](parity-records.json) mirrors the initial requirements. The [source manifest](source-manifest.json) records literal Swift preference keys, default evidence, slash commands, shortcuts, capability methods, UI action labels and persistence sites. Null Windows mappings and pending review flags are explicit unfinished work. Refresh the source inventory with `python windows/docs/generate-source-inventory.py`; this does not overwrite this tracker or change acceptance status.

## Baseline details requiring deliberate Windows mapping

- Mac preferences default to Dark; the left sidebar and main canvas are Solid, right sidebar and alerts Mica, composer and minimap Liquid Glass. Windows must use accurately named supported materials and fallback behavior.
- Both model picker appearances are independent persisted choices. “Maximum” is the display name for internal `max`; choices must come from the live model catalog.
- `/browser` opens Browser settings. Browser panel activation is a distinct workspace action; `/clear` creates a new chat.
- Source continuation dispatch time is the reported reset plus eight seconds; unknown reset means no invented timer. Stored jobs retain access and route snapshots.
- Browser model preferences contain search engine, desktop layout, JavaScript, fraud warning and AutoFill. Restore Tabs is separately defined in `DesktopUtilityPreferences` and defaults to false; tab restoration is per workspace. Passkey behavior in the brief requires a deliberate Windows implementation and verification.
- Projectless workspaces persist; Temporary is a separate explicit eligibility-controlled choice.
- Dynamic tools expose only empty-object, no-additional-properties read-only schemas and must resolve the originating runtime thread, not whichever thread is selected.
